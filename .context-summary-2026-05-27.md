## Key Architecture Decisions
- `JsRuntime` is `!Send + !Sync` → lives on dedicated OS thread with tokio `LocalSet`
- Communication: `std::sync::mpsc` for requests, `tokio::sync::oneshot` for replies
- `Rc<dyn ModuleLoader>` is `!Send` → must be created *inside* the extension thread (pass root_dir PathBuf across thread boundary)
- `v8::Global<T>` bridges scope blocks and runtime phases
- `deno_core::scope!(scope, rt)` borrows `&mut rt` — can't call runtime methods while scope alive
- `load_main_es_module_from_code()` uses module loader only for imports (entry code provided directly)
- `ModuleLoadResponse::Sync` for filesystem reads (no async needed)
- `ResolutionKind` variants: `MainModule`, `Import`, `DynamicImport`
